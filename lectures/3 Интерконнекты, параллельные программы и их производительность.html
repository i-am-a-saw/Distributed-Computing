1

Интерконнекты и общая память

Как несколько вычислителей связаны с одной памятью.

Интерконнект — система связей, по которым вычислительные узлы обмениваются данными. Представь процессоры как рабочие места, память — как шкаф с общими материалами, а интерконнект — как дороги между ними.

UMA и NUMA — как далеко находится память

UMA

Uniform Memory Access

Равномерный доступ к памяти. В простой модели время доступа к любой области общей памяти примерно одинаково для всех процессоров.

Полезная модель для начала: один логический пул памяти и близкая стоимость доступа.

NUMA

Nonuniform Memory Access

Неравномерный доступ к памяти. Память логически общая, но физически распределена по узлам: к локальной памяти обычно обращаться быстрее, чем к памяти другого узла.

Практический вывод: размещение данных рядом с вычислением может влиять на время работы.

Шина (bus): одна общая дорога

Шина — общая линия передачи данных, которой пользуются процессор, память и периферийные устройства. Если несколько устройств хотят передать данные одновременно, нужен арбитраж: выбирается, кто использует линию сейчас, а остальные ждут.

Шина свободна.

Преимущества шины

Просто Легко понять, подключить и сделать относительно недорого.

Гибко Общая магистраль может обслуживать разные устройства.

Ограничения шины

Конкуренция Одновременные передачи делят один ресурс.

Масштабирование При росте числа устройств растут конкуренция и нагрузка.

Единая точка отказа Повреждение магистрали может затронуть всю систему.

Кроссбар (crossbar): отдельные пути между входами и выходами

Кроссбар — коммутационная матрица. При условии, что выходы разные, она позволяет одновременно соединить несколько пар «вход → выход». Если два входа хотят один и тот же выход, они всё равно конкурируют за этот выход.

Почему кроссбар быстр?В лекции подчёркнуты высокая пропускная способность и малая задержка: между входом и выходом достаточно одного коммутационного узла, а независимые пары могут передавать одновременно.
Цена этого быстродействияМатрица требует много коммутирующих элементов и энергопотребления. Чем больше портов, тем дороже становится её построение.

2

Интерконнекты с распределённой памятью

У каждого узла есть собственная локальная память; данные между узлами нужно передавать.

В отличие от модели общей памяти, каждый вычислительный узел здесь хранит свои данные локально. Чтобы узел A использовал данные узла B, информация должна пройти через сеть связей.

Четыре классические топологии

Топология — это правило, по которому соединены узлы. От него зависят число связей, количество промежуточных переходов, возможность параллельного трафика и стоимость сети.

Кольцо (ring)

Идея: каждый узел соединён с двумя соседями по циклу. Сеть проста, но сообщения иногда обходят почти всё кольцо.

По таблице лекции: ширина бисекции 2; p связей; мощность адаптера 3.

Тороидальная сетка (2D torus)

Идея: двумерная сетка, у которой противоположные границы тоже соединены. У узла есть соседи по двум направлениям.

Для квадратного тора по таблице: ширина 2√p; 2p связей; мощность адаптера 5.

Полносвязная сеть

Идея: прямое соединение каждой пары узлов. Путь короткий, но число связей растёт очень быстро.

По таблице: ширина p²/4; число связей p(p−1)/2; мощность адаптера p.

Гиперкуб

Идея: для p=2ⁿ узлов каждый узел соединён с n соседями. Хороший компромисс между количеством связей и расстоянием.

По таблице: ширина p/2; связей ½p log₂p; мощность адаптера 1+log₂p.

Прямые и непрямые сети

Прямой интерконнект

В топологиях вроде кольца или гиперкуба конечные узлы сами соединены друг с другом через соседние каналы. Пакет может пройти через несколько узлов.

Непрямой интерконнект

Узлы соединяются через отдельные коммутационные ступени. В лекции приведены кроссбар и сеть «Омега». Такая схема строится из переключателей, а не только из связей между конечными узлами.

Как выбрать топологию интуитивно?Кольцо дешёвое и простое; тороидальная сетка даёт больше параллельных связей при умеренной степени узла; полносвязная сеть обеспечивает очень короткие пути, но чрезвычайно дорога; гиперкуб поддерживает много связей логарифмически по числу узлов. Реальная производительность зависит также от маршрутизации, пропускной способности каналов и характера нагрузки.

Вопрос: почему полносвязная сеть обычно дорогая при большом числе узлов?

3

Ширина бисекции: сколько данных сеть может пропустить поперёк

Метрика, которая помогает сравнивать топологии по потенциальной пропускной способности.

Возьмём сеть и разделим её узлы на две равные по числу узлов группы A и B. Ширина бисекции — это число связей, пересекающих границу такого разделения, для наихудшего/минимального разреза в используемом определении. Эквивалентная формулировка из лекции: минимальное число связей, которое нужно удалить, чтобы разделить сеть на два несвязанных множества одинакового размера.

Почему метрика полезна? Если алгоритму нужно много данных перегонять из одной половины машины в другую, узкое место может оказаться не в процессорах, а в небольшом количестве связей между половинами.

Сравнение топологий из лекции

Здесь p — число узлов. Формулы — именно для моделей топологий, приведённых на слайде. Для тороидальной сетки подразумевается квадратная 2D-сетка; для гиперкуба p — степень двойки.

Состояние гонки: разбираем по микрошагам

На слайде общая переменная sum изначально равна 100 000. Процессор 1 выполняет sum += 1 000 000, а процессор 2 — sum -= 30 000. Кажется, что это две простые команды. Но прибавление/вычитание обычно включает чтение старого значения, вычисление результата и запись нового. Эти действия могут перемешаться.

Как исправлять гонку

🔒

Критическая секция

Защитить «прочитать → изменить → записать» блокировкой, чтобы одновременно внутрь заходил только один поток.

⚛

Атомарная операция

Использовать операцию, которая выполняет обновление как единое неделимое действие, если для задачи доступна подходящая atomic-примитива.

∑

Частичные суммы

Каждый поток суммирует собственный участок в локальную переменную, потом результаты объединяются редукцией.

ВажноСтавить блокировку «где-то рядом» недостаточно: все обращения, конфликтующие за одно состояние, должны соблюдать один протокол синхронизации. Иначе гонка останется.

Два потока увеличивают общий счётчик на 1 без атомарности. Оба успели прочитать 10, каждый вычислил 11 и записал 11. Какое значение останется?

5

Когерентность кэшей и false sharing

Почему одинаковая переменная может иметь разные копии в кэшах и почему «разные данные» иногда мешают друг другу.

Когерентность кэшей

Процессор часто читает данные сначала из кэша, а не напрямую из оперативной памяти. Если у двух процессоров есть кэшированные копии одной переменной x, а один процессор меняет x, нужно обеспечить согласованность копий. Иначе другой процессор может прочитать устаревшее значение.

Пример со слайда: сначала x = 7. Процессор 1 считает a = 2x, процессор 2 — c = x. Затем процессор 1 записывает x = 12. После этого процессор 2 вычисляет b = 10x.

Лекция перечисляет два подхода к обеспечению когерентности кэшей:

1. Отслеживание (snooping)

Кэши наблюдают за операциями записи/событиями на общей среде и реагируют: например, инвалидируют устаревшую копию.

2. Справочник (directory)

Специальная структура отслеживает, в каких кэшах есть копии блоков, и помогает согласовать их при записи.

Названия приведены в формулировке лекции; конкретные протоколы когерентности могут иметь более сложные состояния и сообщения.

False sharing — ложное совместное использование

Когерентность обычно контролирует не каждый байт отдельно, а блок фиксированного размера — кэш-строку. Представим, что поток A часто меняет переменную countA, а поток B — независимую переменную countB. Логически данные не пересекаются, но случайно расположены рядом в одной кэш-строке.

Почему это «ложное» sharing?Потоки не делят одну логическую переменную, но аппаратная система видит одну общую кэш-строку. Из-за частых записей строка может переходить между кэшами — работа выполняется правильно, но медленнее.

Что делать на практике

По возможности хранить часто изменяемые значения каждого потока отдельно; использовать локальные счётчики и объединять их позднее; при реальной необходимости — выравнивание/заполнение структур так, чтобы горячие переменные не попадали в одну кэш-строку. Конкретный размер строки зависит от архитектуры, поэтому не стоит без проверки зашивать его в код.

6

Как взаимодействуют процессы с распределённой памятью

Message Passing, one-sided communication и PGAS.

Message Passing — передача сообщений

У каждого процесса своя память. Если процессу 0 нужен результат процесса 1, тот отправляет сообщение, а процесс 0 принимает его. В примере на слайде процесс 1 подготавливает текст «Hello from process 1» и отправляет его процессу 0; процесс 0 получает строку и печатает её.

Send(данные, получатель) ↔ Receive(буфер, источник)Условная схема интерфейса; конкретные аргументы и гарантии зависят от API.

Что запомнить: процесс не может просто прочитать переменную другого процесса как локальную. Он передаёт или получает сообщение через поддерживаемый механизм коммуникации. Поэтому важно согласовать отправителя, получателя, тип/размер сообщения и порядок операций.

One-sided communication — односторонняя коммуникация

На слайде этот подход описан как операция, которую вызывает один процесс, чтобы прочитать данные из удалённой памяти или записать значение в память другого процесса. Это может избавить от необходимости в каждой передаче связывать явные вызовы Send и Receive.

Главная проблема — когда можно читать и писать?

Лекция подчёркивает: если процесс 0 пишет в переменную процесса 1, то нужно решить две задачи.

  1. Процесс 0 должен знать, когда безопасно выполнить удалённую запись.
  2. Процесс 1 должен знать, когда значение уже записано и его можно читать.

Варианты из лекции: синхронизировать процессы перед записью и/или добавить ещё одну синхронизацию; либо использовать флаг готовности, который принимающий процесс проверяет. При этом бесконечный частый опрос флага может быть дорогим; корректная реализация должна обеспечить также видимость записи и правильный порядок операций.

Ключевой вывод«Односторонняя» означает, что для инициирования передачи не обязательно нужен парный вызов отправителя и получателя. Это не означает «синхронизация больше никогда не нужна».

PGAS — Partitioned Global Address Space

PGAS-языки представляют память системы как единое глобальное адресное пространство, но оно разделено на партиции. Каждый вычислительный узел имеет быстрый доступ к своей локальной части и может напрямую обращаться к удалённым частям без явного оформления каждой операции в виде сообщения.

Глобальная адресация

Программист может мыслить адресами в едином пространстве, даже если физически данные лежат на разных узлах.

Осведомлённость о локальности

Важно понимать, какие данные локальные («близко»), а какие удалённые («далеко» через сеть). Доступ к ним может стоить по-разному.

Ускорение и эффективность параллельной программы

Сколько времени экономим и насколько хорошо используем p процессоров.

Ускорение S

S = Tserial / TparallelTserial — время последовательной программы; Tparallel — время параллельной программы на p процессорах.

Если последовательная программа работает 100 секунд, а параллельная — 25 секунд, ускорение равно 100/25 = 4. Это означает, что параллельный вариант выполнил ту же работу в четыре раза быстрее.

Линейное ускорение — случай S = p. Например, на 8 процессорах программа стала ровно в 8 раз быстрее. Это идеальный ориентир, но не гарантия: часть работы может быть последовательной, а передача данных и синхронизация отнимают время.

Эффективность E

E = S/p = Tserial / (p · Tparallel)Показывает, какую долю идеальной производительности p процессоров мы получили.

Если на 8 процессорах получили ускорение 4, то эффективность E = 4/8 = 0,5 = 50%. В среднем система дала половину идеального ускорения на каждый процессор. Причинами могут быть ожидание, синхронизация, коммуникация, дисбаланс работы или последовательный участок.

Время параллельной программы

Tparallel = Tserial/p + ToverheadУпрощённая модель из лекции: идеальная доля полезной работы плюс накладные расходы.

Накладные расходы — всё дополнительное, чего не было бы в идеальном равномерном делении: подготовка потоков, коммуникация, синхронизация, ожидание данных и дисбаланс работы. Важно: эта запись — полезная модель для рассуждения, а не точный закон для любой программы.

Закон Амдала: последовательная часть ограничивает ускорение

Даже бесконечно много процессоров не ускорят тот участок, который нельзя выполнять параллельно.

Обозначим через r долю исходного времени программы, которая не поддаётся распараллеливанию. Остальная доля 1−r идеализированно делится между p процессорами. Это допущение намеренно оптимистично: в простейшей формуле не учитываются реальные затраты на коммуникацию и синхронизацию.

S(p) = 1 / (r + (1−r)/p)Идеализированная форма закона Амдала для фиксированного объёма работы без дополнительных накладных расходов.

Почему есть верхняя граница?

Когда число процессоров растёт, параллельная часть может становиться всё короче. Но последовательная доля r остаётся: программе всё равно нужно выполнить её последовательно. Поэтому при p → ∞:

Smax = 1/rНапример, если 10% времени нельзя распараллелить, ускорение в этой модели не превысит 10×.
Пример на пальцахЕсли r = 0,10, то из исходных 100 секунд 10 секунд остаются последовательными. Остальные 90 секунд можно распределить хоть между тысячей процессоров, но суммарное время не станет меньше 10 секунд. Значит, верхняя граница ускорения — 100/10 = 10 раз.

  • При увеличении размера задачи доля последовательной части r во многих случаях уменьшается — но это не универсальное правило: оно зависит от алгоритма и способа измерения.

Закон Густафсона — другой вопрос к параллельности

Не «насколько быстрее та же задача?», а «сколько больше работы успеем за то же время?»

Закон Амдала фиксирует размер задачи и показывает, как последовательная часть ограничивает ускорение. Закон Густафсона-Барсиса смотрит иначе: при добавлении процессоров можно увеличить размер параллельной части задачи и сохранить примерно то же время выполнения.

Sp = (1−r)p + rФормула в обозначениях лекции: r — последовательная доля измеренного параллельного времени; 1−r — параллельная доля.

Если r мало, то большая часть времени приходится на работу, которую можно масштабировать. Тогда объём работы, которую система выполняет за то же время, может быть почти в p раз больше, чем объём, выполнимый последовательной программой за такой же интервал.

Амдал

Размер задачи фиксирован. Увеличиваем p и спрашиваем: насколько меньше станет время? Последовательная часть задаёт предел.

Fixed-size problem

Густафсон

Время примерно фиксировано. Увеличиваем p и спрашиваем: насколько большую задачу теперь можно решить? Масштабируем параллельную работу.

Scaled-size problem

10

Масштабируемость: как ведёт себя программа при росте системы

Не только «быстро ли сейчас», но и «что будет при росте числа процессов и размера задачи».

Лекция называет программу масштабируемой, если при увеличении числа процессов/потоков можно увеличить размер входных данных так, чтобы эффективность E не изменилась. Далее выделены два способа рассматривать рост.

Strong scaling

Сильная масштабируемость

Размер входной задачи остаётся тем же. Меняем количество процессов/потоков и смотрим, насколько лучше получается решать именно этот объём данных.

В терминах лекции рассматривается сохранение эффективности E при том же размере входных данных.

Weak scaling

Слабая масштабируемость

Размер входных данных увеличивается примерно в той же пропорции, что и число потоков/процессов. Каждый процесс получает сопоставимый объём работы.

В терминах лекции эффективность E остаётся неизменной при пропорциональном увеличении задачи и числа процессов.

Пример с разделением работы

Допустим, нужно обработать массив из 8 миллионов элементов. При сильном масштабировании мы оставляем 8 миллионов и добавляем процессы — каждый получает меньший кусок, но увеличиваются возможные расходы на обмен и синхронизацию. При слабом масштабировании при удвоении числа процессов удваиваем и массив до 16 миллионов, чтобы каждый процесс продолжал обрабатывать примерно такой же кусок.

Какие вопросы задавать при оценке?Какое время замеряется? Одинакова ли задача в сравниваемых запусках? Сколько процессов участвует? Выросли ли коммуникации и синхронизация? Сохранилась ли эффективность? Без ответа на эти вопросы сравнение «ускорилось в N раз» может вводить в заблуждение.

Ты удвоил число процессов и одновременно удвоил размер входных данных, стремясь оставить объём работы на один процесс примерно одинаковым. Какой режим масштабирования изучаешь?

Одновременные, параллельные и распределённые вычисления

Три близких понятия, которые отвечают на разные вопросы.

⏱

Concurrent computing

Одновременные вычисления. Несколько задач могут быть запущены в одном временном интервале и продвигаться вперемежку. Это не обязательно означает, что они физически исполняются в один и тот же момент.

⚙

Parallel computing

Параллельные вычисления. Несколько процессов выполняются одновременно на разных вычислительных устройствах и взаимодействуют ради решения задачи.

🌐

Distributed computing

Распределённые вычисления. Несколько программ взаимодействуют друг с другом для решения задачи; часто это процессы на разных узлах, связанные сетью.

Полезная формула-памяткаConcurrency — про структуру и координацию нескольких задач; parallelism — про реальное исполнение нескольких частей работы одновременно; distributed — про взаимодействие отдельных программ/узлов. Эти понятия могут пересекаться: распределённая система вполне может выполнять параллельную работу.

Итоговая проверка: собери лекцию в единую картину

Ответь без подсказок, а затем проверь себя.

1. Какое преимущество есть у кроссбара перед общей шиной?

Несколько независимых пар вход–выход могут передавать данные одновременно, если выходы не совпадают. Шина делит одну общую среду между участниками.

2. Зачем нужна ширина бисекции?

Она характеризует, сколько связей приходится на разрез, разделяющий сеть на две равные части. Метрика помогает рассуждать о коммуникационной пропускной способности между половинами сети.

3. Чем состояние гонки отличается от false sharing?

Гонка — проблема корректности: результат зависит от неконтролируемого порядка операций над разделяемым состоянием. False sharing — обычно проблема производительности: разные переменные попали в одну кэш-строку, и когерентность вызывает лишнюю передачу/инвалидацию.

4. Что гарантирует формула Амдала?

Она показывает ограничение ускорения для фиксированного объёма работы при наличии последовательной доли r. В идеализированной модели S(p)=1/(r+(1−r)/p), а при p→∞ потолок равен 1/r.

5. Когда использовать закон Густафсона как способ мышления?

Когда важен не только запуск неизменной маленькой задачи быстрее, а возможность увеличить объём решаемой задачи при росте числа процессоров и оставить время выполнения примерно тем же.

Чек-лист перед экзаменом

Если можешь объяснить это без формул — ты понял основы. Формулы полезны для точного расчёта, но настоящее понимание означает, что ты можешь предсказать поведение системы и объяснить причину, а не просто подставить числа.
